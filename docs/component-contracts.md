# Component contracts — long form

The full contracts for the marketing and prompt components. `AGENTS.md` carries a short summary of each and points here. Read the section before changing the component, its stories, or a page that composes it. Storybook **Pattern** stories stay the copy source; this file records the details behind them.

## FooterReveal

marketing page root — **FooterReveal.Content** (cover, at least `100dvh`, page background, z-index 1) then **FooterReveal.Footer** (sticky bottom, z-index -1). Scrubs opacity, scale (origin `50% 100%`), and blur (12px → 0) across one footer-height of scroll via `useScroll` / `useTransform`. `will-change` only while that scrub is in progress. Reduced motion: fully visible, no scale or blur, including SSR (`useSyncExternalStore` server snapshot is sharp). The root does not clip, so **GridOverlay** guides still cover the hero and stop at the footer. The marketing hero's guide host is `grid-page bg-body !py-0`, so the expanded **ScrollHorizontal** tile meets the footer with no page-background strip. On the navy field, footer guides use the same tracks and sit under the headline and CTA (`z-0` under `z-[1]`). The wordmark spans the footer width and is cropped at the bottom of the brand panel. Field: **`footerRevealFieldClasses`** (`bg-brand` / `text-on-brand`, `#011272`). The wordmark uses **`--color-brand-soft`**. **FooterReveal.Brand** — headline, **Button** `role="inverse"` `type="button"` (`onCtaClick` opens the project modal; optional `ctaHref` renders an anchor only when a link is passed), `socialLinks` (label + href; `https` opens in a new tab with `rel="noopener"`), and an `aria-hidden` wordmark that spans the footer width (`100cqi` divided by the measured advance width in em) and is cropped at the bottom edge. Links on that field: **`footerRevealFieldLinkClasses`**. Scrollbar stays visible (`scrollbar-gutter: stable` in the grid). Paste **Components/FooterReveal → Pattern — marketing page** or **Pattern — marketing hero**. **FooterReveal.Ruled** is the cream marketing footer on **`footerRevealRuledFieldClasses`** (`bg-body` / `text-brand`, `#011272`). The field and the ruled shell are at least `100vh` and grow when the content is taller. The nav, wordmark, and quiet row are one block, vertically centered in the field when that block fits. Top padding still clears the pinned site nav. A centered stack — Services, Resources, About — is **TextLink**. The list sets Geist sans (the heading and body face) so the links inherit it: `--font-size-4xl` below `sm`, `4rem` from `sm` (no type token is 4rem). Those three links set `!text-brand` (`#011272`) so **TextLink**'s `text-fg` does not paint them near black. **TextLink** keeps its solid underline, medium weight, and focus ring. The WhatMatters wordmark is fitted to the footer width (`100cqi` / measured em) and stays fully visible at 390, 1440, and 2560. The quiet row is the WM mark with WhatMatters © 2026, randy@whatmatters.so, and Created by WhatMatters 2024–2026. Below `md` that row stacks and stays centered. There is no cropped wordmark, no two-column nav, and no social row. Dark theme keeps the field on `--color-on-brand`. **No content defaults:** **FooterReveal.Ruled** requires `wordmark`; `links`, `email` (+ `emailHref`), `mark`, `copyright`, and `credit` render only when passed. **FooterReveal.Brand** requires `headline`, `ctaLabel`, and `wordmark`; `socialLinks` renders only when passed. The app owns every string and address. Paste **Pattern — ruled grid footer**. **Pattern — marketing hero ruled grid** uses it under the existing hero. **FooterReveal.Brand** stays the navy field and still crops its own wordmark. See **ADR-0030**.

## HeroTileStack

marketing hero image fan — `tiles` (`src`, `alt`, optional resting `offsetX` / `offsetY` / `rotate` / `zIndex`). A fine pointer over the stack pushes each card left or right away from the pointer's x (closer = stronger) through `useSpring` on x and rotate. Default `strength` (`120`) is a gentle shift that stays near the stack; raise it for a wider scatter. Vertical offset comes from pointer velocity (`useVelocity`): `velocityFactor` (default `0.02`) and `maxVertical` (default `24`) set a small clamped y nudge that springs back to 0 when the pointer slows. Tiles are square, at most **400px** (`tileSize` / `--hero-tile-size`), and scale with the stack; below `md` they form a tighter pile. Scatter distances scale with the painted tile. The root clips the inline axis (`overflow-x-clip`); the row does not clip. Reduced motion: resting fan, no scatter. Coarse pointers: a tap scatters once from the tap point (same gentle horizontal push, no velocity nudge), holds, then springs back. The marketing hero pattern places **SiteNav** above the fan and sizes the hero with `min-h-[calc(100svh-var(--site-nav-height))]`, `shrink-0`, and `justify-center-safe` (`--site-nav-height` is the expanded band). When the copy is taller than that minimum, the section grows and the content starts below the nav with the section's top padding. Hero lines use `text-wrap: balance`. “Austin,” and “Texas” stay together on the default lead (non-breaking space). The sequenced hero keeps “Austin,” and “TX” together the same way (`whitespace-nowrap`). Paste **Components/HeroTileStack → Pattern — marketing hero**. **HeroIntro** is the page `h1` on **`type-display-2`** at normal weight and display-2 leading, the same size and line-height as the gallery statement. There is no display-1 We Are WhatMatters headline. The sequenced hero h1 is only “An Austin, TX studio specializing in brand and product design.” A rock **RiveHand** sits inline immediately after “TX”, inside the same nowrap phrase (`inline`, about 1.15em drawn, centered on the line, `aria-hidden`). That heading has no second sentence and no circle or pill. The default hero still passes “We're a design and product studio based in Austin, Texas.” as `lead` without a sequence. The point hand sits inline in the gallery statement after “is a first impression”, in place of the pill. `lead` is the first sentence (it wraps, including from `md`) and children always start on the next line, centered. **HeroIntro** sits on `grid-page` (same `--grid-max`, margin, gap, and column count as the guides), columns 4–9 from `lg` (`lg:col-start-4 lg:col-end-10`), full width of that page grid below `lg`. The tile fan is last in the hero. See **ADR-0032**, **ADR-0034**, **ADR-0035**.

## TextSequence

masked word reveal — children mix text and **`TextSequence.Shape`** (`variant` `asterisk` \| `pill` \| `diamond` \| `dots` \| `double-pill` \| `circle` \| `smiley`, `tone` `brand` \| `brand-soft` \| `accent` \| `info-muted`). Words slide up behind a mask; shapes pop (scale/rotate) halfway between neighbors. `stagger`, `delay`, `trigger` (`mount` \| `inView`), `idle` (default off: asterisk spin, pill stretch), `lines` (default on, so wrap re-splits), `emphasis` (`alternate` default \| `none`). Parent owns the type step. `className` is layout only. Shapes are inline SVG about 1.15em tall (pills about 2.2em wide) with a 14px floor, centered on the line without growing the leading. Fills are `brand`, `brand-soft`, `accent`, and `info-muted` (softer tones are two-stop token gradients). `aria-hidden`. `prefers-reduced-motion` skips the split and the idle loop; server and no-JS render that rest state. GSAP + SplitText + `useGSAP` are imported only here (ADR-0037); the rest of WMDS stays on `motion/react`. **HeroTileStack → Pattern — marketing hero text sequence** sequences the intro only. That copy is **HeroIntro** `step="display"` as the page `h1` (`type-display-2`, normal weight, display-2 leading, the same size and line-height as the gallery statement). A rock **RiveHand** sits inline immediately after “TX”. The sequenced hero heading is only that Austin sentence. **ScrollHorizontal.Intro** runs the gallery statement through it inside the real `h2` (`emphasis="none"`, `trigger="inView"`, once when that panel scrolls into view). The heading keeps the plain sentence. **FooterReveal → Pattern — marketing hero with sequenced gallery** shows the hero subtext sequence and that statement together. Copy **Components/TextSequence**.

## ScrollHorizontal

marketing gallery directly under the hero — `items` (`id`, `label`, optional `color`), optional `heading` (`sr-only` while the window is pinned, visible above the row when motion is reduced; omitted when `intro` is set), optional `intro` (**`ScrollHorizontal.Intro`** — **Badge** label pill (neutral, the category pill), `type-display-2` statement at normal weight through **TextSequence** (`emphasis="none"`, once when the panel scrolls into view; shapes about 1.15em: asterisk after screen, point **RiveHand** after impression, diamond after yours; plain accessible name “Every screen is a first impression and we make yours the one they remember.”), **Button** `role="secondary"` labeled Start a project (no className, no icon); first panel of the track, left edge on the page-grid content start (`--grid-margin` inside centered `--grid-max`), then translates off with the tiles; clears `--site-nav-height`; the badge names the section; reduced motion stacks it above the native row and keeps that inset), `expandLast` (default false), optional `expanded`, `className` on the root only. A `300svh` track (`shrink-0`, so a flex parent keeps that height) and a sticky `h-svh` window (one card wide, centered) translate the row from the first card centered to the last: `(items.length - 1) * (item width + gap)`, measured from the DOM. From `sm`: **400×500**, `gap-8` (32px). Below `sm`: **280×350**, `gap-4` (16px). Radius `rounded-xl` (`--radius-xl`, 12px). Each card is a solid token fill. The label is `sr-only` (the accessible name). Omitted colors cycle `--color-brand` (`#011272`), `--color-brand-soft`, `--color-primary`, `--color-info-muted`, and `--color-accent`. `prefers-reduced-motion` and `MotionConfig` `reducedMotion="always"`: no transform, height auto, not sticky, native horizontal overflow, `py-12`. SSR stays on the motion shell; the OS query is applied in `useLayoutEffect` before paint, and `motion-reduce:` covers that paint. **`expandLast`** (default false) lengthens the track to **`400svh`** (`shrink-0`) so the horizontal travel keeps the same scroll distance and one extra viewport grows the last tile. The grow is a `clip-path` inset on a full-viewport layer: the centered card expands to the `h-svh` window edge to edge and the radius reaches 0. Earlier tiles fade. The window then releases and that full-bleed tile scrolls away. **`expanded`** is an optional slot on that section (mounted for the motion layer and the reduced-motion section; one is hidden). Reduced motion keeps the native scroller and follows it with the last tile as a static `h-svh` section. Paste **Components/ScrollHorizontal → Pattern — project gallery**. The marketing hero patterns place it under the hero and pass `expandLast`. The section ends on that tile. **FooterReveal → Pattern — marketing hero** sets `!py-0` on the guide `grid-page` after the gallery so the tile meets the footer with no page-background strip. Reduced motion's static `h-svh` section meets it the same way. See **ADR-0036**.

## RiveHand

decorative hand on the marketing hero headline, from `public/rive/interactive-icon-set.riv` (`@rive-app/react-canvas`). `hand` `'point'` (`31_Cigarette`, cigarette removed) or `'rock'` (`29_Rock`). `size` is the box (`em` tracks the headline). `active` sets `Boolean 1`. `idle` (default true) holds that input for 1.1s, then waits a random 1–2s before the next pulse, per hand, while the tab is visible and the sized hand box is in view. `entrance` is `slide-up` (rock, clipped at the baseline), `grow` (point, 200ms later, origin at the grip), or `none`. `aria-hidden` defaults to true. `handFill` reads `--color-surface` (fallback `--color-background-surface`; white in light mode); `outline` reads `--color-brand` (`#011272` in both themes; hardcoded fallback `#011272`). `inline` places the hand in a text line. The canvas is larger than the artboard padding so the drawn hand is about 1.15em, the drawn hand is centered on the line, and a zero-height slot keeps the line box. Inside a TextSequence that slot pops on the beat halfway between the words beside it, with the same scale, rotation, and `back.out(1.8)` ease as the circle and pill. Idle starts after that pop. The sequenced hero places the rock hand inline immediately after “TX”, inside the same nowrap phrase. It pops on the beat after TX. The gallery statement places the point hand inline after “is a first impression”, in place of the pill. `entrance="none"`. `aria-hidden` stays true. Outline stays `--color-brand` (`#011272`). Reduced motion draws one static frame once the canvas box has size, then pauses. The sequence pop and idle timers stay off. The server and the hydration render both use that resting pose (no `translateY(100%)` or `scale(0)`); the entrance starts after mount only when motion is allowed. ## PromptBar

wide prompt pill — inline **TextArea** (`rows={1}`, one line when empty, grows through **3 lines**, then scrolls) and an **IconButton** `sm` send control (Lucide **ArrowRight**) inset with even padding. The pill owns focus; the send control does not draw a second ring. Placeholder **Ask anything…**. Enter sends; Shift+Enter inserts a newline. Send stays disabled and muted until the draft has text, then uses **`--color-brand`** (`#011272` / `bg-brand`). No new Button role. Voice and attachments are not part of this version. Copy **Components/PromptBar → Pattern — prompt bar**. Optional `start` holds the brand mark (**Avatar** `size="md"`, the send circle's size) and `end` holds extra inset **IconButton** `sm` controls before send. On the marketing pages **PromptBar** appears inside **ChatDock** (**Components/ChatDock → Pattern — chat dock**): pinned to the bottom of the page grid (`--grid-max: 40rem`, above the safe area, under **SiteNav**), it opens into a non-modal chat window instead of handing off to a separate ask page. Do not hand-roll the pin, and do not restyle **SiteNav**.

## ChatDock

The site assistant. At rest, a **PromptBar** pinned to the bottom of the page grid (`--grid-max: 40rem`, above the safe area, under **SiteNav**), with the brand `mark` (**Avatar** `size="md"`) in its `start` slot. Hovering the bar shows the `suggestions` that carry a `prompt` as **Button** `secondary` pills above it, one `--motion-stagger` apart; touch never shows them. Focusing, clicking, or typing opens a non-modal window around the same composer, and Escape or **Close chat** folds it back. One **PromptBar** serves both states, so the composer is on screen every frame and never jumps. From `md` the window is an opaque card on the composer's bottom edge that grows up and out of it on the medium tier — height, 16px wider on each side, pill radius to the shell radius; the mark folds out of the composer (the header carries it), and the composer keeps its width, rising only by the `disclaimer` line that opens under it. The header, conversation, and rows fade in one `--motion-stagger` apart, a `--motion-beat` after the window starts; on close they fade first, the window folds back into the bar, and the hover pills return once it has folded. Below `md` the window fills the screen and rises from the bottom edge, and falls back on close. Escape while opening, or a click in the composer while closing, reverses from where it is. Reduced motion crossfades the window in place at full size; nothing slides, so the mark and the disclaimer line switch at once and the composer steps up by that line. The window is the shared overlay header (mark, `title`, `subtitle`, close only — no send or expand arrow), the conversation (`role="log"`: `greeting`, then `messages`; the visitor's turns sit on `bg-brand-tint`, replies are plain text; a **Status** dot thinking row while `thinking`), and the suggestion rows (**Button** `layout="row"`) until the first message; the composer and the `disclaimer` caption sit on top of it. The thread stays pinned to the end while the reader is there.

**Follow-ups.** `followUps` takes the same items as `suggestions` (`{ id, label, prompt? }`; an `icon` is not shown) for the latest reply only. They show while the last message is an assistant reply and `thinking` is off, and disappear the moment the visitor sends — ChatDock hides them itself before the app clears them, so they never sit beside a pending reply. Choosing one calls `onSuggestionSelect`, then `onSend` with its `prompt` when it has one; an item without a `prompt` (for example **Start a project**) only calls `onSuggestionSelect`. The press does not take focus from the composer, and a keyboard choice hands focus back to it. They rise in one `--motion-stagger` apart (fast tier) and leave at once. `followUpsPlacement="inline"` (default) renders them as **Button** `layout="row"` rows in the conversation, directly under the reply, each led by Lucide **CornerDownRight**, in a group named `labels.followUps` (**Suggested follow-ups**) — 44px targets below `md`, 36px from `md`. `followUpsPlacement="composer"` renders text-only **Button** `secondary` pills between the conversation and the composer; they wrap, so at 390 three take about 150px from the conversation. The app decides which replies get follow-ups; **Pattern — chat dock** holds the state (set from `ask`'s result, cleared on send).

The app owns `messages`, `thinking`, `followUps`, `onSend`, and `onSuggestionSelect`; ChatDock never fetches or parses Markdown (`content` is text or rendered Markdown). `placement="inline"` is for previews only. Copy **Components/ChatDock → Pattern — chat dock**. See **ADR-0039**.
