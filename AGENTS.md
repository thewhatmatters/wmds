# WMDS — agent notes

- **Brand:** **WhatMatters** (joined) — never "What Matters" in copy or docs.

## Storybook-first

Long-form contracts for **FooterReveal**, **HeroTileStack**, **TextSequence**, **ScrollHorizontal**, **RiveHand**, **PromptBar**, and **ChatDock** are in **`docs/component-contracts.md`**. Read that section before changing one of them.

- **Storybook** is the canonical catalog — **Getting started → Guides → Foundations → Components** (ADR-0026, amended 2026-10-03). **Components** are A–Z (`Components/{Name}`); related exports share a family folder (`Components/{Family}/{Name}` — **Button**, **Card**, **Checkbox**, **Radio**). **Components → Overview** groups every export by category from **`src/storybook/componentCatalog.ts`**. **Guides** holds cross-component guidance. Product pages and flows (the WhatMatters site, PitchKit) live in their own apps, not in WMDS Storybook.
- **Theme** lives in `src/theme/` — `colors.css` (semantic roles) + `theme.css` (Tailwind `@theme` bridge). Storybook is the source of truth, not Paper.
- **Dark mode:** `[data-theme="dark"]` on `<html>` or any ancestor — same token names, swapped values in `colors.css`.
- **Authoring (WMDS repo):** **Pattern-first** — ship **components + props + Storybook examples**, not utility recipes for apps. Tailwind utilities belong **inside** `*Styles.ts` / component files. See **ADR-0004**.
- **Consuming apps:** use exported components and typed props; `className` for layout only — not re-theming. Page layout utilities (`gap`, `grid`, `max-w`) are fine between components.
- **Documentation voice:** Storybook component meta and **Pattern** stories describe **WMDS contracts only** — props, anatomy, composition, when to use. Do **not** link or name external design systems in Storybook docs or component bullets here. ADRs record decision history; agents and app engineers follow **Pattern — …** stories and **Best practices** sections.
- **Theme tokens:** Semantic roles in **`src/theme/colors.css`**; typography in **`src/theme/typography.css`** (`type-*` utilities, geometric scale; **display-1/2/3** are fluid via `clamp` — display-1 hits **5rem** on desktop and scales down to **2.5rem** on mobile); motion in **`src/theme/motion.css`**; page spine in **`src/theme/grid.css`** (`--grid-*`, `grid-page` / `band`, `--leading-base`). **`--spacing` stays 4px** — do not re-scale; baseline is 8px. See **ADR-0007**, **ADR-0008**, **ADR-0009**, **ADR-0010**, **DESIGN.md → Grid**. Use **`typographyClass()`** — not raw `text-sm` in document copy. **`type-eyebrow`** (`typographyClass("eyebrow")`) is the small uppercase mono caption for editorial labels — column captions over **IndexList** rows and filter panel titles ("/ Filters", "/ Date"); write the text in sentence case and mark a "/" marker `aria-hidden`. Not for app UI section labels (`overline`) or secondary text (`caption`). See **ADR-0040**.
- **Page layout:** Every Storybook **Guides** page and consuming product page starts on **`grid-page`**; use **`band`** + responsive column spans for content alignment. Constrain a specific experience by overriding **`--grid-max`** on that wrapper (for example, `960px`) rather than replacing the grid with an arbitrary centered container.
- **Scroll fade:** use **`scroll-fade-y`** / **`scroll-fade-x`** on the element that owns overflow to hint at clipped list or rail content. The mask is scroll-aware, disappears when no overflow exists in supporting browsers, and follows inline direction for RTL. Keep the surface fill/border on a wrapper; customize with `--scroll-fade-size` only when the default 12% / 40px cap does not fit. Copy **Foundations → Scroll fade → Pattern — …**.
- **Example grid inspector:** Every page-level Storybook **Guides** page composes the Storybook-only **`ExampleGridControls`** helper to toggle guides/theme and edit `--grid-max` / `--grid-column-gap` live. It composes exported WMDS controls and **must not** ship in consuming product UI.
- **Motion:** Duration tiers in **`src/theme/motion.css`** — **fast** (hover/focus), **medium** (panels/layout), **slow** (rare). Single **`--ease-standard`**. CSS via `motionTransition()`; Motion via `motionTransitionProp()`. Choreography tokens `--motion-stagger`, `--motion-beat`, `--motion-blur-reveal` through `motionStaggerSeconds()`, `motionBeatSeconds(n)`, `motionBlurReveal(reduce)`, and `readMotionDurationSeconds(tier)` — Show code never hard-codes a blur, stagger, or duration. See **ADR-0008**. Storybook wraps `<MotionConfig reducedMotion="user">`.
- **Icons:** **[Lucide](https://lucide.dev/icons/) only** until further notice — import from **`lucide-react`** in components, stories, and examples. Peer dependency, not bundled; use `stroke-current` / `ButtonIcon` for sizing. See **Foundations → Icons**.
- **Button:** pill by default; **`layout="row"`** for flat full-width detail/settings lines (**`width="hug"`** sizes a row to its content with a tight gap — inline disclosure triggers); **`align="start"`** left-aligns a pill label and **`emphasis="quiet"`** puts `role="outline"` on the `border-border` hairline (full-width suggestion pills — **Pattern — suggestion pills**); **`layout="nav"`** for **NavList** rows (`selected`). Six **roles** (`primary`, `secondary`, `ghost`, `destructive`, **`inverse`** — surface fill and brand text, for a brand-blue field, **`outline`** — hairline border and transparent fill). Patterns: action, **`row`**, **`nav`**, `icon`, `count`, `status` morph, **`mono`** + **`endIcon`** (accent arrow square) — mutually exclusive where documented. No slots. [Motion reference](https://motion.dev/examples/react-multi-state-badge).
- **Avatar:** circular identity — required `name`, optional `src`, initials → **User** fallback; sizes `xsm` / `sm` / `md` (default) / `lg` / `xl` (20–128px). Optional `presence={{ tone, label, pulsing? }}` — rim dot via **Status** dot tokens (not the **Status** component). **`avatarSizeForCluster()`** for header rows; **`size="sm"`** in **Dropdown.Item** `start`. Not clickable — wrap at call site. Agents: copy **Components/Avatar → Pattern — …**; see **ADR-0017**.
- **IconButton:** circular icon-only control. Patterns: toolbar (ghost), `fab`, `loading`, native `title`, **`inset`** (compact dismiss inside Chip), **`render={<a/>}`** (circular brand / icon links), **`pressed`** (toggle — `aria-pressed`, pressed fill and a filled glyph while on; votes, stars). Compose **Tooltip** for tokenized hover/focus labels and pass `title=""` to avoid duplicate native UI. **`aria-label` required** — use `Button` when text is needed.
- **Kbd:** semantic keyboard keycap — one physical key per **Kbd**; compose multiple keycaps for shortcuts. Sizes `sm` | `md`; add `aria-label` when symbolic labels need spoken expansion. Display-only — never interactive on the keycap itself. Numbered choice rows pair trailing **Kbd** digits with **`useKbdChoiceKeys`** so `1`–`9` select the same way a click does while focus is not in text entry (a focused checkbox or radio still takes digits); pass `scope` (a ref) to act only while focus is inside that element, as in a chat gate (see **Pattern — numbered choice keys**). Copy **Components/Kbd → Pattern — keyboard shortcut**.
- **TextLink:** inline anchor for navigation — `variant="prose"` (default) inside prose: canonical solid underline, stronger hover decoration, and focus ring. **`variant="quiet"`** for headline-size text and list titles: no underline at rest, an underline scaled to the text on hover and focus, the same focus ring; inherits size and weight from the heading around it — never inside running prose. `external` opens a new tab and appends Lucide **SquareArrowOutUpRight** with spoken context. Inherits surrounding type size; `className` is layout only. Use **Button** for actions. Copy **Components/TextLink → Pattern — inline prose link** or **Pattern — quiet title link**.

Opens on hover/focus, closes with Escape, and does not open on touch. No essential or interactive content. Disabled native controls need the documented focusable wrapper. Copy **Components/Tooltip → Pattern — …**.

- **Card:** `Card.Header`, `Card.Body`, `Card.Footer`. Layout cards (`padding="none"`): header/footer on the shell; **`Card.Header`** is two horizontal slots (`start` | `end`) at **16px** (`px-4`). **`end` is always trailing** (`ml-auto`) — overflow / **MoreMenu** stays on the right even when `start` is omitted. **`Card.Body` is a square composition slot** with a **2px** horizontal gutter — no inner pad, no radius, **no default fill**. The **occupant** dictates how the body region looks; use **`cardLayoutBodyOccupantInsetXClasses`** (`px-3.5` / 14px) + **`cardLayoutBodyOccupantPadYClasses`** (`py-[16px]` / literal 16px vertical) when body content should align with header/footer (2px + 14px = 16px horizontal). Shape config lives in **`src/theme/shape.css`**: shell **`--radius-card-shell: 16px`**, body occupant **`--radius-card-body: 14px`**. Radius-only media → **`cardLayoutBodyOccupantRadiusClasses`**; inset gray/chart wells → **`cardLayoutBodyOccupantWellClasses`** or **`cardLayoutBodyOccupantDotGridWellClasses`**. A headerless layout **Card.Body** densifies the shell top to 2px (`pt-[2px]`) — same density as footerless / `bodyTerminal` bottom; **`headerless`** is only an override for wrapped slot composition. A direct terminal **`Card.Body`** automatically fills stretched cards and gets the 2px bottom shell inset; **`bodyTerminal`** is only an override for wrapped slot composition. Pin a layout height on the root (`className`) with Header + Body + Footer — Header/Footer stay put; **Card.Body** scrolls (2px gutter unchanged; no new variant). See **Components/Card/Card → Pattern — pinned height**. `variant="surface"` is elevated; **`variant="outlined"`** uses **`shadow-soft-card`** with no stroke (same elevation as layout `surface`). Radius stays **`--radius-card-shell`**. Default **`shape="rounded"`**. **`shape="flush"`** only when a parent owns outer chrome. Simple cards: `padding="md"`.

- **ChatDock:** the site assistant — a **PromptBar** pinned to the bottom of the page grid (`--grid-max: 40rem`, under **SiteNav**) with the brand `mark`; hovering shows `suggestions` that carry a `prompt` as **Button** `secondary` pills above it; focusing, clicking, or typing opens a non-modal chat window around the same composer (shared overlay header with `title` / `subtitle` / close, `greeting`, `messages` (visitor turns on `bg-brand-tint`, replies as plain text), `thinking` row, suggestion rows — **Button** `layout="row"` — until the first message (a row that sends hands focus to the composer as the rows leave), `disclaimer` under the composer). Below `md` it fills the screen, rising from the bottom edge. Phones keep the window inside the area a keyboard leaves visible. Start a project runs as a gate, not a dialog — paste **Pattern — start a project gate** and return it from **Pattern — chat dock**'s `renderStartProject`. Never put a form inside `content`. The app owns `messages`, `followUps`, votes, the gate's open state, and `onSend`; suggestions without a `prompt` (for example **Start a project**) only call `onSuggestionSelect`. No full-page chat, no header send/expand arrow, no voice. `placement="inline"` is for previews only. Copy **Components/ChatDock → Pattern — chat dock** (it holds the follow-up state, the votes, and Start a project). See **ADR-0039**. Full contract: **docs/component-contracts.md → ChatDock**.

- **Sheet:** dismissible edge overlay — `side="bottom" | "end" | "start"` only (**no `top`** — not a product pattern); same scrim/focus/scroll lock as **Dialog**; bottom drawer or side detail rail; header/footer pinned, body scrolls; **hairline borders** on scroll regions. Compose to mirror resolved chrome (title, **Select**, well, footer). **`aria-busy`** on **Card** / page region; shapes **`aria-hidden`**. Not chart-mark state — swap region for **Chart.Loading** or live marks. See **Components/Skeleton**, **Components/Chart** Card pattern stories.

## Components (atomic design — rebuild in progress)

Brad Frost tiers under **`src/components/`**:

| Tier | Path | Catalog placement | Export |
|------|------|-------------------|--------|
| Atoms | `atoms/{Name}/` | `Components/{Name}` or `Components/{Family}/{Name}` | Yes |
| Molecules | `molecules/{Name}/` | `Components/{Name}` or `Components/{Family}/{Name}` | Yes |
| Organisms | `organisms/{Name}/` | `Components/{Name}` or `Components/{Family}/{Name}` | Yes |
| Guidance pages | `src/guides/{Name}/` | `Guides/{Name}` | No |

**Import rules:** atoms ← molecules ← organisms ← guides. Molecules may compose other molecules (e.g. TaskRows + Chip). Atoms never import other components.

**Molecule composition:** Every visual affordance inside a molecule must **compose atoms** — not hand-rolled mini-controls. Leading icons → **`ButtonIcon`** / **`BadgeIcon`**. Dismiss / toolbar actions → **`IconButton`** (use **`inset`** inside chips). Counts on segments → **`BadgeSegmentCount`**. Status labels → **`Badge`**. Fields → **`Input`**. Primary/secondary actions → **`Button`**. Detail / settings rows → **`Button layout="row"`**. TaskRows detail actions → **`TaskRows.Detail variant="button"`** ( **Button** `size="xs"` ); tags → read-only **Chip** `size="sm"`. If an atom’s size or pattern doesn’t fit, **extend the atom** and its Storybook spec first — do not fork a one-off in the molecule (see **Chip** removable dismiss). The molecule keeps shell, layout, and state. Rule: **`.cursor/rules/wmds-atomic-composition.mdc`**. Gate: **`npm run validate:composition`**.

**Catalog** — see `src/package.manifest.ts` → `atomicExports`. Reclassify via ADR only. **Card** is a molecule (ADR-0005).

When adding a component: create its folder in the correct atomic tier, title its story `Components/{Name}` (or `Components/{Family}/{Name}` when it joins a family), add an entry with a category and one-line description to **`src/storybook/componentCatalog.ts`**, add it to the manifest, and export it from `src/index.ts` alphabetically within tier. Document **Usage → Anatomy → Best practices → Examples** — the story is the contract (ADR-0004).

**Storybook copy source:** Show code is **off by default** (`preview.tsx` + **`storyMetaDocsDefaults()`** on component meta). Only **Pattern — …** stories opt in via **`storyCopySource()`** / **`withStoryCopySource()`** — drop-in imports + JSX, never CSF. **Anatomy**, **Reference**, and meta Usage/Best-practices markdown do not get Show code.

- **`src/guides/{Name}/`** — cross-component guidance, Storybook title **`Guides/{Name}`**. Storybook-only; never in `src/index.ts`.

## Guardrails

Rules from the 2026-10-03 audit. The check that enforces each one is in parentheses. Full record: **`docs/audits/2026-10-03.md`**.

- **Before pushing:** `npm run lint`, `npm run typecheck`, `npm run test:unit`, `npm run build`, `npm run test:interactions`. CI runs all five, plus `check:changelog`, `check:pack`, and a publish dry run.
- **Stories and tests are type-checked.** `tsc -b` covers everything under `src/`, not only shipped code. (CI: Typecheck)
- **Story types:** `StoryObj<typeof meta>` when stories pass args. `StoryObj<typeof Component>` when stories supply required props in their own JSX. (Typecheck)
- **Hooks in a story `render` need a named function** — `render: function NameRender() { … }`, not an arrow. (Lint)
- **Description plus Show code:** `parameters: withStoryCopySource({ docs: { description } }, code)`. Spreading `...storyCopySource()` after a `docs` key drops the description. (Typecheck)
- **`typographyClass()` takes a role** (`ui-label`, `caption`, …), not a type-scale name (`label`, `supporting`). (Typecheck)
- **A pipe inside a Markdown table cell in a template literal is `\\|`.** A single backslash is dropped. (Lint)
- **New component:** add it to `src/package.manifest.ts` and `src/index.ts` together. Every package a shipped module imports is a dependency or a peer dependency. (`npm run build` → `scripts/validate-manifest.mjs`)
- **Heavy or optional dependencies stay inside the component that needs them** (GSAP in **TextSequence**, Rive in **RiveHand**, visx in **Chart**) — never in shared `lib/` code. The package builds one module per source file so apps only load what they import.
- **Everything `dist/*.css` references ships in `dist`** — fonts and theme partials. (`validate-manifest.mjs`)
- **Accessibility violations fail story tests.** A story with a known violation is listed in the block at the end of its story file and in the audit record. Do not add to that list — fix the component, or raise it. (CI: Storybook tests)
- **Play functions:** do not assert on a counter the moment a state flips. Wait for the value to hold, with real time (`settledRockFrameCount`) — `waitFor` also re-runs on DOM mutations.
- **Unit tests do not use the network.** `vitest.setup.ts` holds runtime WASM requests.
- **Dependency ranges are pinned** — no `latest`.
- **Every change apps can see goes in `CHANGELOG.md`** under the top entry, with the exact steps an app takes under **Consumer actions** (or **None.**). Name any **Pattern — …** whose Show code changed so apps re-copy it. If the top entry's version is already on npm, start a new entry and bump `package.json` to match — a minor bump (`0.x.0`) for anything that breaks an app while the major is `0`, a patch otherwise. (CI: Changelog → `npm run check:changelog`)
- **Package docs are generated.** After changing a story's Show code, a story title, the catalog, the manifest, or a component bullet under **Storybook-first**, run `npm run docs:generate` and commit `docs/patterns/`, `docs/exports.json`, and `docs/components.md`. Never edit those by hand. (CI: Package docs → `npm run check:docs`)
- **Show code compiles in a consumer app.** Pasted unchanged into Next 16 + React 19 + strict TypeScript + `eslint-config-next`, every Pattern passes `tsc` and `eslint --max-warnings 0`. That means: a complete module (imports + an **exported** component, never a bare JSX fragment), app data and callbacks as **typed props** (WMDS types such as `ChartCartesianPoint`, `SelectOption`), no placeholders (`…`, `/* toggle */`, empty `{}` attributes), no unused imports or variables, every WMDS import actually exported by the package, and `&apos;` for apostrophes in JSX text. Plain `<img>` is allowed. (CI: Show code in a Next app → `npm run check:show-code`, fixture in `fixtures/next-consumer`)
- **The tarball is checked.** A new export path or shipped asset goes in `package.json` → `files` / `exports` and in the required list in `scripts/check-pack.mjs`. Sources, stories, tests, decision records, and the Rive WASM never ship. (CI: Package contents → `npm run check:pack`)
- **Consumer skills live in `skills/<name>/SKILL.md`** (`use-wmds`, `upgrade-wmds`, `report-wmds-gap`) and install into apps with `npx skills add 'thewhatmatters/wmds#v<version>' …`. Frontmatter `name` matches the folder; `description` says when to use the skill. Update them when a rule they quote changes (props vs utilities, Consumer actions, the pattern header, the PR checklist). Contributor-only skills stay in `.cursor/skills/`.
- **`bin/wmds-check.mjs` ships to apps** (`npx wmds-check`). When a rule it enforces changes here (raw controls, layout-only `className`, tokens, pasted-pattern headers), update the check and `src/lib/wmdsCheck.test.ts` with it. (CI: Unit tests)
- **Releases publish from CI only**, from a `v<version>` tag, through `.github/workflows/release.yml` with npm trusted publishing. Never run `npm publish` locally (the one exception is the owner's first publish in **`docs/releasing.md`**) and never add an npm token to the repo.
